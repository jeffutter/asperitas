## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while reviewing TASK-014 (crates/asperitas-logging/src/usb.rs:73-86, `extend_peri_to_static`). TASK-014's stated goal was to replace `core::mem::transmute` with "embassy-hal-internal's own sanctioned unsafe primitive" for extending a `Peri<'_, T>` borrow to `'static`. It landed on `Peri::new_unchecked(*p)`. But `Peri::new_unchecked` in embassy-hal-internal-0.5.0/src/peripheral.rs:22-34 is marked `#[doc(hidden)]` and its own doc comment says explicitly: "For use by HALs only. If you're an end user you shouldn't use this, you should use `steal()` on the actual peripheral types instead." asperitas-logging is not a HAL — it is exactly the "end user" this comment is warning off. The crate does provide the actual sanctioned end-user API for this: each concrete peripheral type gets an inherent `pub const unsafe fn steal() -> Peri<'static, Self>` generated by the `peripherals_definition!` macro (embassy-hal-internal-0.5.0/src/macros.rs:15-25), specifically for conjuring a `'static` Peri outside HAL-internal code. TASK-014 satisfied its acceptance criteria literally (no `transmute`, builds, clippy-clean) but did not satisfy the ticket's actual Resilient-axis intent: "unsafe code that doesn't need to be as unsafe as it is." It now depends on a `#[doc(hidden)]` item that is not part of embassy-hal-internal's public contract (no semver guarantee it keeps working, even though it happens to be technically `pub`), instead of the item the crate's own docs point end users to. Note this is not a one-line swap: `steal()` is an inherent function generated per concrete peripheral type, not a method on the `PeripheralType` trait `extend_peri_to_static<T: hal::PeripheralType>` is generic over, so it can't be called generically through that bound without further design work (see plan).

3. Decide the resolution:
   a. Preferred: drop the generic `extend_peri_to_static<T: hal::PeripheralType>` helper and call `T::steal()` directly at each of the three call sites in `init()` (`hal::peripherals::USB_OTG_FS::steal()`, `hal::peripherals::PA12::steal()`, `hal::peripherals::PA11::steal()`), each wrapped in its own small `unsafe {}` block. Only if (a) proves awkward for a concrete reason discovered while implementing (e.g. it materially hurts readability at the three call sites): keep the generic `extend_peri_to_static` helper but change its safety doc comment to explicitly justify using `Peri::new_unchecked` (a `#[doc(hidden)]` HAL-internal item) over `steal()` — state why `new_unchecked(*p)`, which reconstructs from the already-owned `Peri<'_, T>` argument via `Copy`, is preferred here to `steal()`'s "conjure from nothing" semantics, and why depending on a `#[doc(hidden)]` non-public-contract item is acceptable for this project. Do not choose (b) merely because it's less typing — (a) is the actually-sanctioned path and should be the default.
4. Implement the chosen resolution in crates/asperitas-logging/src/usb.rs.
