## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Objective audio verification needs a known stimulus into the Pod input and a recording of what comes back out. Until that exists every DSP criterion is a listening test, and the project cannot tell a regression from a bad cable.

The loop is closed inside the device rather than through a purchased converter: a short male-to-male 3.5 mm cable from the Pod's line-level output to its line-level input. Both jacks sit on the same codec behind the same MCLK and share one ground, so the two failure modes an external interface would have introduced simply do not exist — no clock slip between independent converters, no hum through a shared host USB ground. Stimulus level is set digitally instead of by hunting a pad switch, and the Pod's line-level input driving its own line-level output is naturally matched, which retires the gain-staging trap in docs/reference/daisy-pod.md as a test hazard. The remaining cost is one cable plus firmware that generates stimulus and records the return, tracked as TASK-038.

What this route cannot do is notice a fault common to both directions. A shared clock misconfiguration, or a channel swap in the capture code itself, yields a clean self-measurement on a broken board. Hence criterion #2: the cheapest thing that is not the device grading its own homework. Keep it human permanently — automating it would reproduce the blind spot this whole arrangement is vulnerable to.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] #3 HUMAN: end-to-end level through the loop is recorded at a fixed digital stimulus level (−20 dBFS suggested) with no clipping anywhere, giving the loop gain later measurements normalize against
- [ ] #4 HUMAN: any hum, buzz or DC offset visible in the captured return is characterized with an amplitude, or recorded as absent
- [ ] #5 HUMAN: the physical setup — cable type and length, measured loop gain, stimulus level, independent-observer findings — is written into docs/reference/daisy-pod.md as the lab setup note

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Revised 2026-09-09: the original version of this ticket assumed a permanently-attached small USB audio interface. Dropped on cost and bulk once the self-loopback option was priced — a patch cable replaces the box, and the single-clock-domain property is strictly better for measurement.

Consequence: the drift criterion that was here (fix 48 kHz on host and device, record clock slip over 60 s) is deleted deliberately, not deferred. With one codec there is nothing to drift. TASK-035's alignment requirement changed from 'tolerate drift' to 'verify the offset is fixed', which is a stronger assertion.

Real playing material still works without a host analog path: excerpts from audio/instruments/ are stored in QSPI and replayed as stimulus by TASK-038.
